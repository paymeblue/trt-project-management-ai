<objective>
The video call room is functionally correct but presentationally and
operationally sub-enterprise: the stage has no height management so it
letterboxes into a thin strip, the invite editor outranks the call itself,
there is no live awareness of who actually joined or how long the call has
run, and the single most destructive action in the app ("End for everyone",
which kills the call for every participant) fires on one unconfirmed click.

Purpose: make the call room read and behave like a professional meeting tool,
and make call ending provably correct across every exit path rather than
correct-by-accident.

Output: one new pure helper module with full unit coverage, a restructured
call room (full-height stage + secondary People/Chat panel + live status bar),
a confirmed destructive end, a remote-end notice, and a written exit-path
audit table that enumerates all seven ways a user can leave a call room.

## Verified SDK facts (checked against the installed @stream-io/video-react-sdk 1.39.3)

Do not re-derive these; do not invent hooks beyond them.

- `useCallStateHooks()` exposes (confirmed in
  `node_modules/@stream-io/video-react-bindings/dist/src/hooks/callStateHooks.d.ts`):
  `useCallCallingState`, `useCallStartedAt` (documented verbatim as "the actual
  start time of the current session. Useful for calculating the call
  duration"), `useParticipants`, `useRemoteParticipants`, `useParticipantCount`,
  `useCallSession`, `useCallEndedAt`, `useCallEndedBy`, `useCallMembers`.
- `CallingState` string values: `unknown`, `idle`, `ringing`, `joining`,
  `joined`, `left`, `reconnecting`, `migrating`, `reconnecting-failed`,
  `offline`.
- **Remote end behavior (confirmed by reading the SDK's `watchCallEnded` in
  `@stream-io/video-client/dist/index.es.js`):** when someone else calls
  `call.end()`, every other client receives the `call.ended` WS event. The
  state handler runs FIRST — it sets `endedAt` (from the call response) and
  `endedBy` (from `e.user`) — and only THEN does `watchCallEnded` invoke
  `call.leave({ reject: false })`, which transitions `callingState` to `LEFT`.
  So by the time this component sees `LEFT`, `useCallEndedAt()` and
  `useCallEndedBy()` are already populated. That ordering is what makes the
  remote-end notice in Task 3 reliable rather than racy.
- `CallControls` accepts exactly one prop: `onLeave?: (err?: Error) => void`.
- `SpeakerLayout` renders a root with `.str-video__speaker-layout__wrapper`,
  which is `flex-grow: 1; overflow-y: hidden`. **This is the root cause of the
  letterboxed strip**: `flex-grow` only does anything inside a flex-column
  parent that itself has a bounded height, and today's parent is a plain
  `<div className="min-w-0 flex-1 overflow-hidden rounded-xl border">` with no
  height and no `display: flex`. Combined with
  `.str-video__speaker-layout .str-video__participant-view { aspect-ratio: 16/9 }`,
  the stage collapses to whatever the 16:9 tile needs at the container's
  width and leaves dead space below.
