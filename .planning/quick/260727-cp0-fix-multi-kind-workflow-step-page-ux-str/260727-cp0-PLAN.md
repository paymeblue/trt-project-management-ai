<objective>
Fix the dead-end UX on multi-kind workflow steps (e.g. `confirmation_correction` = `yes_no_upload` + `ack` + `readiness`): a user fills the yes/no sub-form, skips its own Submit, clicks the page-level "Complete step", and gets the opaque server error "Complete this step's form before marking it done." Two display-layer fixes:

1. A RECORDED `yes_no_upload` requirement renders as a green "recorded" banner (answer + upload name) instead of an empty form, matching the checklist branch's existing completed banner.
2. The page-level Complete step button is disabled with a "Still needed: …" hint whenever any state-gated required kind is unfulfilled.

Purpose: users can see what is already recorded and what is still outstanding, instead of being stranded by a generic server rejection.
Output: display-only changes. `completeGraphStep`'s `fulfilledKinds` superset check stays the authoritative gate — nothing in the engine or in any server action changes behavior.
</objective>
